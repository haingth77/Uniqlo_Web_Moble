Docker · Jenkins · step-by-step

Repo có hai đường CI tách biệt: Flow A dựng chính máy chủ Jenkins bằng Docker, và Flow B là pipeline chạy test mỗi lần có job. Mỗi bước ở cột trái đi kèm đoạn code thật ngay bên phải — không cần mở file nguồn để đối chiếu.

Flow A — Build Jenkins host (image) ──▶ Flow B — Pipeline chạy trên host đó Mấu chốt nối 2 flow: volume /var/run/docker.sock ở A4
cho phép lệnh docker compose up ở B5 chạy được.
A
Dockerfile → Docker image → Jenkins container
Mục tiêu: một Jenkins controller chạy trong Docker, tự gọi được docker compose.
docker_ci_cd/Dockerfile docker_ci_cd/docker-compose.yaml
  1. 1
    Base image

    Lấy image Jenkins LTS kèm sẵn JDK 21 làm nền. Đã có Jenkins server hoàn chỉnh, ta chỉ bổ sung công cụ còn thiếu.

    Dockerfile
    FROM jenkins/jenkins:lts-jdk21
  2. 2
    Cài Docker CLI + Compose

    Chuyển sang root để cài docker.io + curl, tải docker-compose v2.24.0 về làm CLI plugin, cấp quyền chạy, rồi xoá cache apt cho nhẹ image.

    Bước then chốt: Jenkins sẽ cần gọi docker compose để chạy test ở Flow B.

    Dockerfile
    USER root
RUN apt-get update && \
    apt-get install -y docker.io curl && \
    mkdir -p /usr/local/lib/docker/cli-plugins && \
    curl -SL "https://github.com/docker/compose/releases/download/v2.24.0/docker-compose-linux-x86_64" \
         -o /usr/local/lib/docker/cli-plugins/docker-compose && \
    chmod +x /usr/local/lib/docker/cli-plugins/docker-compose && \
    rm -rf /var/lib/apt/lists/*
  3. 3
    Hạ quyền

    Trả lại user thường sau khi cài xong. Không để Jenkins chạy bằng root, thu hẹp rủi ro bảo mật.

    Dockerfile
    USER jenkins
  4. 4
    Khai báo service

    build: . dựng image từ Dockerfile. Port 8080 (web UI) và 50000 (kết nối agent). Volume /var/jenkins_home giữ dữ liệu qua mỗi lần restart; /var/run/docker.sock cho container điều khiển Docker của host (Docker-outside-of-Docker).

    Chính socket này là cầu nối để Flow B chạy được container test.

    docker_ci_cd/docker-compose.yaml
    services:
  jenkins:
    build: .
    user: root
    ports:
      - "0.0.0.0:8080:8080"
      - "0.0.0.0:50000:50000"
    volumes:
      - /var/jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      - GIT_CONFIG_COUNT=1
      - GIT_CONFIG_KEY_0=safe.directory
      - GIT_CONFIG_VALUE_0=*
    restart: unless-stopped
  5. 5
    Build & khởi động

    Compose build image (nếu chưa có) rồi tạo và chạy container Jenkins.

    $ docker compose up --build -d
  6. 6
    Jenkins sẵn sàng

    Giờ có một Jenkins controller chạy trong Docker, tự gọi được docker / docker compose — đúng môi trường mà Flow B cần. Truy cập web UI để cấu hình job.

    $ open http://localhost:8080
B
Jenkinsfile → job SCM chạy trên Jenkins
Mục tiêu: mỗi job kéo code, chạy Playwright trong container, xuất report, dọn dẹp.
Jenkinsfile docker-compose.yml (gốc repo)
  1. 1
    Tham số job

    Khi bấm Build, pipeline hỏi 2 lựa chọn: ENVIRONMENT và BROWSER.

    Jenkinsfile · parameters
    parameters {
    choice(name: 'ENVIRONMENT', choices: ['QA', 'Staging'],
           description: 'Select environment to run tests against')
    choice(name: 'BROWSER',
           choices: ['chromium', 'firefox', 'webkit', 'All Browsers'],
           description: 'Select browser ("All Browsers" = run on all 3)')
}
  2. 2
    Suy ra biến môi trường

    BASE_URL tính từ ENVIRONMENT (QA → site UK, Staging → site VN); BROWSER = all nếu chọn All Browsers.

    Hai biến này được truyền xuống container test ở bước 5.

    Jenkinsfile · environment
    environment {
    BASE_URL = "${params.ENVIRONMENT == 'QA'
        ? 'https://www.uniqlo.com/uk/en/'
        : 'https://www.uniqlo.com/vn/en/'}"
    BROWSER  = "${params.BROWSER == 'All Browsers' ? 'all' : params.BROWSER}"
}
  3. 3
    Options

    timestamps() gắn giờ vào log; timeout 30 phút để job không treo; buildDiscarder chỉ giữ 20 build gần nhất.

    Jenkinsfile · options
    options {
    timestamps()
    timeout(time: 30, unit: 'MINUTES')
    buildDiscarder(logRotator(numToKeepStr: '20'))
}
  4. 4
    Stage: Checkout

    checkout scm kéo đúng branch/commit mà job được cấu hình trỏ tới (SCM = repo này).

    Jenkinsfile · stages
    stage('Checkout') {
    steps {
        checkout scm
    }
}
  5. 5
    Stage: Run Tests

    Compose (dùng docker-compose.yml ở gốc repo) dựng service playwright-tests, chạy suite vào BASE_URL với BROWSER đã chọn. --exit-code-from lấy mã thoát của container test làm kết quả stage.

    Jenkinsfile · stages
    stage('Run Tests') {
    steps {
        echo "Environment: ${params.ENVIRONMENT} | URL: ${env.BASE_URL}"
        sh 'docker compose up --abort-on-container-exit \
                --exit-code-from playwright-tests'
    }
}
  6. 6
    Lưu kết quả

    post → always của stage: publishHTML gắn Playwright report vào build; archiveArtifacts lưu report + test-results để tải về. Chạy dù pass hay fail.

    Jenkinsfile · post (Run Tests)
    post {
    always {
        publishHTML(target: [
            reportName : "Playwright - ${params.ENVIRONMENT}",
            reportDir  : 'playwright-report',
            reportFiles: 'index.html',
            keepAll    : true
        ])
        archiveArtifacts(
            artifacts        : 'playwright-report/**/*,test-results/**/*',
            allowEmptyArchive: true
        )
    }
}
  7. 7
    Dọn dẹp & báo cáo

    post → always của pipeline: docker compose down --volumes gỡ container + volume, tránh rác giữa các lần chạy. Sau đó in PASSED / FAILED.

    Jenkinsfile · post (pipeline)
    post {
    always  { sh 'docker compose down --volumes' }
    success { echo "PASSED on ${params.ENVIRONMENT} (${params.BROWSER})" }
    failure { echo "FAILED on ${params.ENVIRONMENT} (${params.BROWSER})" }
}
Nguồn: Dockerfile · docker-compose.yaml · Jenkinsfile — trích nguyên văn từ repo tại thời điểm dựng sơ đồ.
